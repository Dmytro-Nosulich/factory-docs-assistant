Every number comes from a script in this repo. Each generated section names the `make` target that writes it, and the hand-written paragraphs name the command or result file behind their numbers. The stage 1 report (structured extraction) is in [docs/reports/stage-1.md](docs/reports/stage-1.md).

**How it works (S2-14).** `make ask` can refuse in two places. Before the model call, a score gate refuses when the best reranked chunk scores below `[answer] min_rerank_score`. After the call, the model can answer `not_in_documents`. The threshold and the answer prompt were chosen on 20 development questions (`evals/dev_questions.toml`, drafted by Claude at the user's request and reviewed by the user), which are kept apart from the gold set and the test set. The threshold rule was written down before the run (`docs/METRICS.md`). With it, the gate refuses no answerable development question by construction, so its false-refusal rate on new questions is still unmeasured (S2-16).

**What the numbers say.** The model's own status did the refusing: with the gate off, both prompt versions refused all 12 unanswerable questions and none of the 8 answerable ones. The gate refuses only the questions whose best chunk is clearly off topic. Three near misses score above the lowest answerable question (V05, -0.80): hydrogen (0.18, also above V01 at -0.07), helium (-0.26) and HLP 68 (-0.26). Their chunks state the same kind of fact for a neighbouring gas or product, so no threshold can separate them (`docs/ISSUES.md` I-010; scores per question in `evals/results/refusal.md`). The gate still matters: it skips the model call for 9 of the 20 questions, and it refuses even if the model would have answered. Prompt v2 did not change the refusals, but it fixed most of the language bug: in this run, v1 wrote 6 of the 8 English answers in another language (5 German, 1 Swedish), v2 only 1 (German, V11; per question in `evals/results/refusal.md`, history in `prompts/CHANGELOG.md`). `make ask` now uses v2 with the threshold -1.03 (user's choice). Twenty questions and one run per version: one question moves a rate by 5 to 12 points.

## Error analysis
`make answer-errors RUN=evals/results/runs/20261124T213807Z.json` lists every test question of this run that failed the deterministic pass or that the quality judge did not call correct: 7 of 24. For each one it gives the expected answer, the outcome, the top reranker score against the score gate, and the context rank of the chunk that holds the evidence quote (the gold-set hit rule). It also shows the same question in the S2-19 calibration answers, which were made with the score gate off. It calls no model and writes no file. Rules in `docs/METRICS.md`. `tests/test_answer_errors.py` checks every number quoted below against these committed files. The analysis covers this run; a later `make eval` writes a new run file and can change it.

The 7 questions fall into four errors:

| # | Questions | Category, language | Expected | Actual | Cause |
| --- | --- | --- | --- | --- | --- |
| 1 | T01, T02, T04 | answerable; pl, sv, es | -17 °C; Varning; 0,725 kg/l | refused by the score gate, no model call | top scores -1.87, -1.64, -2.84, below the gate at -1.03, with the evidence in the context |
| 2 | T11 | similar_doc; fr | approx. 165 °C | `not_in_documents`; `missing` gives 165 °C for "another variant" | the chunk that names LZB 125 was not retrieved, and the sibling-product rule fired |
| 3 | T12 | similar_doc; en | no flash point ("Flash point: None") | refused by the gate (-1.65); gate off, `not_in_documents` that quotes "None" | the answer chunk is at rank 10 of 10, and the model reads "None" as no value |
| 4 | T06, T17 | answerable, outdated_version; en | the main fact plus a second point | the main fact only (judge: partially correct); T17 in German | the model answers the narrow question; a language slip that no scorer checks |

### 1. The score gate refuses answerable questions in Polish, Swedish and Spanish
- **What:** T01 (pl, flash point of Borvida acetone), T02 (sv, signal word of BIOGON N) and T04 (es, density of F 80 Desengrasante) never reached the model. Their top reranker scores (-1.87, -1.64, -2.84) are below `[answer] min_rerank_score = -1.03`, although the chunk with the evidence quote was in the context, at rank 1, 7 and 3. For T01 the top hit is the evidence itself (`Temperatura zapłonu : -17 °C`). With the gate off (calibration answers), the model answered all three, with the key fact in its claims.
- **Why:** the threshold came from the development questions, where the lowest answerable top score was -0.80 (V05, uk; `evals/results/refusal.md`). The development set has no Polish, Swedish or Spanish question (en 8, uk 5, de 4, fr 2, it 1). The five answerable test questions in other languages (T03, T05-T08) score between -0.39 and 1.89 (`evals/results/eval.md`). So the cross-encoder gives these three a lower score even when it ranks the right chunk first. Its scores rank chunks within one question; they are not calibrated across languages. Three questions cannot separate language from other causes, and T12 (en) is gated too (error 3).
- **What the gate costs here:** with the gate off, the model alone refused all 6 unanswerable test questions and 2 of the 18 others (T11, T12). With the gate on, 5 of the 18 were refused. On this test set, the gate stopped no wrong answer and added three false refusals. What it saves is model calls: 9 of the 24 questions cost nothing.
- **Likely fix:** this was found on the test set, so the threshold is not changed because of it (`docs/ISSUES.md` I-010). It needs development questions in pl, sv and es: the same rule then gives a new threshold. The other options are a threshold per language, or no gate, since the model refused every unanswerable development question on its own.

### 2. T11: the sibling-product rule fires on the right product
- **What:** the French question asks for the boiling point of LAUDA LZB 125 antifreeze. The evidence chunk (D053-s-0010, section 9, `approx. 165 °C (ASTM D 1120)`) is at context rank 10 of 10, and the model saw it. It answered `not_in_documents`, and its `missing` says the context has only the sheet for "LAUDA Antifreeze LZB x25", whose boiling point is about 165 °C, but "ce produit est une autre variante" (this product is another variant). The gate-off answer says the same. The trap value, 108 °C from the ROWE coolant (D052, rank 7), was not stated.
- **Why:** the name "LZB 125" is not in the chunk. D053 names its products only in section 1 (D053-s-0001: `This safety data sheet pertains to the following products: LZB 125: 5 L / LZB 225: 10 L / LZB 325: 20 L`), and that chunk was not retrieved. The chunk header shows the title from `data/manifest.csv`, "LAUDA Antifreeze LZB x25", which is our own shorthand for that list. Prompt v2 says that a fact about "another model, size, grade or variant" does not answer the question. So the model refused instead of guessing that x25 covers 125. That is the safe way to fail: it did not give the sibling's 108 °C.
- **Likely fix:** put each document's product identifiers in its chunk headers (contextual chunk headers, a stretch item), or name the products in the manifest title. Loosening the prompt rule is the wrong fix: the same rule keeps sibling values out of answers. No forbidden fact was stated in this run (0 of 7 traps with forbidden facts).

### 3. T12: the right document, the answer chunk last, and "None" read as no value
- **What:** the question asks for the flash point of CRC Brakleen Brake Parts Cleaner in the 55 gallon drum. The expected answer is that it has none: D056 section 9 says `| Flash point | : None |`. The right document holds context ranks 1 (section 1), 3 (the text before its first heading) and 10 (section 9, the evidence). Ranks 2 and 4 to 9 are other documents: mostly section 9 chunks of other SDS (D052, D050, D048, D053, D057, D001), plus the OSHA flammable-liquid criteria (D066). The top score, -1.65, is below the gate, so no model call was made. With the gate off, the model answered `not_in_documents`, and its `missing` says "Its Section 9 lists the flash point as \"None\"".
- **Why:** two failures. First, the question's product words match the right document's section 1, while its section 9 offers only the word "None". The section 9 chunks of other products, which state real flash points, likely look closer to the question, so the answer chunk only just fits in the context. Second, the model reads "None" as "no value given", although the SDS states that the product has no flash point. Prompt v2 already says that "a clear negative statement in a chunk ... is an answer", but a table cell that reads "None" did not trigger that rule. The judge graded the gate-off answer incorrect, and the user graded it correct, for its content (`docs/ISSUES.md` I-011).
- **Likely fix:** an example in the next prompt version: a table value of "None" or "not applicable" is an answer. Measure it on development questions with such values. For retrieval, filter by product when the question names one (a title match), or use contextual chunk headers, as in error 2.

### 4. Partial answers: the main fact only, and one answer in the wrong language
- **What:** T06 and T17 pass the deterministic scorers, because the key fact is in the claims, but the judge says `partially_correct`. T06 gives "5 or more employees", but leaves out the next part of the same sentence in the cited chunk D070-s-0006: `even if you have fewer than 5, it makes sense to write down what steps you have taken`. T17 names `configuration_type`, but leaves out `Please note that styles cannot be mixed`, which is in the cited chunk D075-s-0014. T17 is also written in German, for an English question with only English chunks in its context. It is the only one of the 15 shown answers in this run that is not in the question's language. The gate-off answer to T17 is German too (and it does mention that the styles cannot be mixed).
- **Why:** the questions ask only for the main fact (how many employees, which setting). The reference answers add a second point, and the key facts hold only the main fact. So the model answered what was asked, and the judge, by its rules, counts an omitted reference point as partial (I-011). This is as much about the test labels as about the model. The language slip is the I-009 bug, which prompt v2 reduced but did not remove (1 of 20 on the development questions). Neither scorer of `make eval` checks language; only `make eval-refusal` does.
- **Likely fix:** write the reference answers to the question as asked, or add the second point as a key fact. Add the language check of `make eval-refusal` to the deterministic scorers, so that a wrong-language answer fails. A language check in code after the answer, with one retry, would catch the bug before the user sees it.

### Pattern
- **Retrieval found the right document in all 7 cases,** and the evidence chunk was in the context every time. The failures come later: the score gate (errors 1 and 3), the refusal and sibling rules applied to incomplete or terse chunks (errors 2 and 3), and the reference answers and language (error 4).
- **The system fails safe:** all 5 failed questions are refusals. The quality judge called none of the 13 answers with claims incorrect, the faithfulness judge found every claim supported (15 of 15), and no forbidden fact was stated. For safety documents, a wrong refusal is the better failure, but here it costs 5 of 18 answerable and trap questions.
- **Caveat:** one run, 24 questions, one judge. Each error rests on one to three questions, so these are leads for the next development round, not measured rates.

## What to improve next
Each item answers an error above or an open issue. Every change would be chosen on development questions and then measured once on the test set, never tuned on it.

1. **Score gate (error 1, I-010):** add Polish, Swedish and Spanish development questions and recompute the threshold by the existing rule. Also measure a threshold per language and no gate at all, on development questions only.
2. **Prompt answer v3 (errors 2 and 3):** an example that a table value of "None" or "not applicable" is an answer. Keep the sibling-product rule, but say that a product listed in the document's identification section is the document's product. Measure it with `make eval-refusal` on new development questions, including sibling and negative-value cases.
3. **Product identity in chunks (errors 2 and 3, decision 19):** contextual chunk headers that carry each document's product identifiers and section path. This is the stretch item that may also close the retrieval gap between `fixed` and `structure` chunks (MRR@10 0.703 against 0.615 with hybrid + rerank).
4. **Language (error 4, I-009):** add the language check to the deterministic scorers and the CI gate, and re-ask once in code when an answer comes back in the wrong language.
5. **Test labels (error 4):** make each reference answer match its question, or turn every reference point into a key fact, so that the scorers and the judge measure the same thing. Changing labels after a run is a test-set change, so record it as such in `evals/test_set.toml` and in this report.
6. **Judge calibration (I-011):** grade a new sample that includes wrong answers, so that kappa means something. Then decide whether a refusal whose `missing` holds the right value should count as correct.
7. **Smaller items:** count prompt tokens with a real tokenizer instead of 4 characters per token (I-009), test stemming for BM25 (I-008), and give CI its own spending limit (I-012).
