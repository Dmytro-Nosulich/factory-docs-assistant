## Goal
Build a service that extracts structured data from raw "dirty" texts into valid JSON by a schema, compares a provider (cloud) model with a local model, and justifies the production choice with numbers. ~9 hours of course work (plus data preparation).

## Course requirements (summary of the assignment)
- Data: at least 30 texts, 10 of them hand-labeled = golden set. Texts must be truly dirty: varied length, typos, missing fields, mixed languages. No personal data.
- Step 1 (~2h): schema (Pydantic or JSON Schema), at least 6 fields, at least 1 enum and at least 1 nested object or list. Baseline prompt. Provider model via API with structured output. Retry and timeout. Run all texts and save results.
- Step 2 (~2h): local model (Ollama or other OSS) behind a shared interface with the first. Sampling params (temperature, top_p) in config; compare at least 2 configurations. Measure per model: field accuracy on the golden set, % valid responses, latency p50/p95, cost per 1000 documents.
- Step 3 (~3h): prompts in separate versioned files with a changelog (at least 2 versions, with what changed and why). Validate every response against the schema; invalid gets one repair attempt, then marked `failed`. Log model, prompt version and sampling params with every result.
- Step 4 (~2h, after the 26.10 Q&A): table model x prompt version x sampling with all step 2 metrics. Analysis of 3-5 characteristic errors (what instead of what, and why). Final production choice in 1 paragraph + conditions under which you would change it.
- Stretch (no extra points): third (cheap provider) model; automatic regression run of prompts on the golden set; response caching.
- Technical: Python 3.11+, any provider + a local model, keys in `.env` (only `.env.example` committed), one-command run, up to $5 API budget, local model must work on an ordinary laptop.
- Repo must contain: service code and schema; `prompts/` with versions and changelog; `data/` with texts and golden set; `results/` with model outputs; `REPORT.md`; `README.md` (how to run, what to install).
- Not needed: UI, deployment, fine-tuning, big dataset, perfect accuracy.
